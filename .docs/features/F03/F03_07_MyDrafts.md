# F03_07 我的草稿（工作空间）

> 本页为系统通用能力在 F03 场景下的落地说明。  
> **代码对齐口径**：当前后端未提供独立 `drafts` 资源，采用组合能力实现。

## 1. 范围与目标

- 目标：让用户在工作空间查看和继续处理自己保存的草稿数据。
- 范围：草稿列表、草稿详情跳转、草稿继续编辑。
- 非目标：设计全新的草稿专属数据模型与专属控制器。

## 2. 页面与交互

### 2.1 页面类型

- 页面类型：列表页（筛选 + 表格 + 分页 + 行内操作）。
- 入口：工作空间「我的草稿」。

### 2.2 列表核心字段

| 字段 | 说明 |
|---|---|
| 草稿ID | 文档草稿主键（`docId`） |
| 文档业务编码 | 草稿业务编码 |
| 文档名称 | 草稿标题/名称 |
| 业务模块 | 业务归属 |
| 更新时间 | 最近保存时间 |
| 操作 | 查看详情、继续编辑 |

## 3. 业务规则

- **R-MD-001 草稿归属**：默认只显示当前登录用户创建的草稿（通过 `createdByUserId` 过滤）。
- **R-MD-002 数据隔离**：草稿记录与正式数据隔离，草稿不进入“已归档/正式查询”结果。
- **R-MD-003 编辑闭环**：草稿可重复保存；提交后从草稿集合流转到后续流程状态。

## 4. API（代码对齐）

> 当前实现为“组合模式”，非独立 `/drafts` 资源。

| 资源路径 | 方法 | 用途 | 代码口径 |
|---|---|---|---|
| `FDC_URL/api/archive-management/pending-documents/query` | POST | 查询草稿列表（按 `createdByUserId` + 草稿状态） | `PendingDocumentQueryController.query` |
| `FDC_URL/api/archive-management/archives/{archiveId}` | GET | 草稿详情/详情统一读取 | `ArchiveManagementController.getArchiveDetail` |
| `FDC_URL/api/archive-management/pending-documents` | POST/PUT | 保存草稿（`submitMode=DRAFT`） | `PendingDocumentWriteCommand` 口径 |

## 5. 权限与安全

- 列表与详情均执行数据范围校验（至少按用户归属）。
- 草稿编辑权限与文档创建/维护权限绑定。
- 审计记录至少包含：用户、草稿ID、动作（创建/保存/提交）、时间、结果。

## 6. 测试计划

| 用例ID | 场景 | 期望结果 |
|---|---|---|
| TC-MD-01 | 当前用户查询我的草稿 | 仅返回本人草稿 |
| TC-MD-02 | 草稿保存后刷新列表 | 更新时间变化，状态仍为草稿 |
| TC-MD-03 | 草稿提交后再查草稿列表 | 提交记录不再出现在草稿列表 |

## 7. 验收标准（AC）

- **AC-01**：我的草稿不依赖 F03 列表页筛选条件，按用户归属展示。  
- **AC-02**：用户可从草稿列表进入详情并继续编辑。  
- **AC-03**：草稿提交后正确流转，列表状态一致。
