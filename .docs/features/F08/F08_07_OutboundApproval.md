## 2. 节点目标

- 在**销毁决策已批准**的前提下，对**实物/载体出库**进行库房侧审批：库位释放、出库凭证、与库存账一致。
- 与「销毁审批」分离：**先批准出库，再执行销毁**，满足库房管理与双人牵制等内控要求。

## 3. 参与角色

- 库房管理员 / 出库审批人（`03_Security.md` 待登记）
- 必要时监销人或第三方物流对接（本期可占位）

## 4. 输入 / 输出

| 类型 | 内容 |
|---|---|
| 输入 | 冻结清单 + 销毁审批通过记录；计划出库时间、承运/交接信息（若适用） |
| 输出 | 出库单或出库审批记录；库存状态变更（扣减在库量、在途销毁等，字段待对齐数据模型） |

## 5. 业务规则（草案）

- **R-01**：电子件-only 的档案是否跳过实物出库节点（**系统配置**或按载体类型分支，待订）。
- **R-02**：出库数量与清单明细**逐项勾稽**；缺件须拦截或记异常。
- **R-03**：出库完成后才允许进入「实施销毁」节点登记最终结果（或允许并行监销，待业务确认）。

## 6. 页面与 API（占位）

- 出库待办、扫码/勾对明细、确认出库。
- API：出库审批、出库确认、与 `F05`/库存模块接口（若共用）。

## 8. 验收要点（草案）

- 实物档案未出库确认时，实施销毁不可标记「已完成」；电子档案路径可配置跳过或自动出库确认。
