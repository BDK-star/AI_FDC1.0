# F08_00 销毁文档总览

> **定位**：F08 销毁文档的主流程与节点边界；各节点细节见 `F08_01`～`F08_08`。  
> **说明**：全局 Manifest 中「销毁申请、电子流查询、自动鉴定、自动触发…」等表述偏能力列举，**与本版按业务节点拆分的电子流不一致**；以本目录流程为准。

## 1. 流程节点（顺序）

```mermaid
flowchart LR
  A[1 提交申请] --> B[2 审核申请]
  B --> C[3 业务鉴定]
  C --> D[4 综合鉴定]
  D --> E[5 汇总清单]
  E --> F[6 销毁审批]
  F --> G[7 出库审批]
  G --> H[8 实施销毁]
```

| 节点 | 业务含义（摘要） | 规格文档 |
|---:|---|---|
| 1 | 申请人发起销毁需求，勾选/导入拟销毁档案，形成销毁申请单（草稿可保存、提交后进入审核） | `F08_01_SubmitApplication.md` |
| 2 | 对申请材料的完整性、权限与合规前置条件进行审核（通过/驳回/退回补充） | `F08_02_ReviewApplication.md` |
| 3 | 业务侧对档案是否满足销毁业务条件进行鉴定（可批量、可按明细） | `F08_03_BusinessAppraisal.md` |
| 4 | 综合/档案管理侧对保管期限、鉴定结论等进行复核与综合判定 | `F08_04_ComprehensiveAppraisal.md` |
| 5 | 将已通过鉴定的明细汇总为正式销毁清单（可冻结版本、供后续审批与出库对照） | `F08_05_AggregateList.md` |
| 6 | 有权人对汇总清单与鉴定结论进行销毁决策审批 | `F08_06_DestructionApproval.md` |
| 7 | 库房/实物出库环节审批（与销毁实施解耦：先批准出库再执行销毁） | `F08_07_OutboundApproval.md` |
| 8 | 现场或委托销毁执行、回执与结果登记，档案状态终结，触发报告与审计留痕 | `F08_08_ExecuteDestruction.md` |

## 2. 页面顶部固定区（全流程常显）

> 无论主单处于哪个节点，销毁页面顶部均必须展示以下固定信息区。

### 2.1 流程节点图（固定展示）

- 组件位置：页面最上端，位于业务操作区之前。
- 节点集合：固定为 8 个节点（与本页 §1 完全一致，顺序不可变）。
- 节点视觉状态（仅三类）：
  - **已完成**：当前节点之前且已通过的节点。
  - **进行中**：当前处理节点（唯一）。
  - **未完成**：当前节点之后的节点。
- 状态判定来源：主单当前阶段（见本页 §4 状态机）+ 历史流转记录。
- 交互建议（可选）：点击节点可查看该节点处理记录，但不改变当前处理节点。

### 2.2 申请单与申请人信息（固定展示）

| 字段 | 展示规则 | 口径说明 |
|---|---|---|
| 申请单号 | 始终展示 | 生成规则：`DT` + `yyyyMMdd` + 五位流水号（同日从 `00001` 递增） |
| 状态 | 始终展示 | 显示主单当前状态中文值（如：待业务鉴定、待销毁审批） |
| 当前处理人 | 始终展示 | 显示当前待办处理人；若为会签/多人并行，显示多人名单或“等 N 人”并支持展开 |
| 申请人 | 始终展示 | 显示申请人姓名（可附组织信息，格式待子文档细化） |

> 编码示例：`DT2026042700001`。  
> 若主单处于终态（已完成/已驳回/已撤回），“当前处理人”显示最后处理人或 `—`，具体以工作流引擎口径为准。

## 3. 横切能力（非独立「流程节点」）

以下能力跨节点存在，**不单独占一个流程序号**，在各节点规格中按需引用：

- **电子流查询 / 待办**：申请人、审批人、鉴定人视角的列表与详情穿透。
- **自动规则**（若启用）：例如保管期限届满提示、批量预选候选档（须在规则引擎或定时任务规格中定义触发点，并映射到节点 3/4 的入口数据）。
- **自动清理**：通常指实施销毁完成后的存储、索引、借阅封锁等**技术收尾**（归在实施销毁节点与系统任务，而非单独业务审批节点）。
- **销毁报告**：可在节点 8 完成后**自动生成**或**半自动生成**（模板、签章、导出为子规格）。

## 4. 状态机（草案，待与 `02_Workflow.md` 对齐）

> 以下为**主单级**示意；若存在「一单多明细」，需补充明细级状态及向主单聚合规则（可参考 F07 主单/明细模式）。

| 主单阶段 | 对应节点 | 说明 |
|---|---|---|
| 草稿 | 1 | 未提交 |
| 待审核申请 | 2 | 已提交 |
| 待业务鉴定 | 3 | 审核通过 |
| 待综合鉴定 | 4 | 业务鉴定完成 |
| 待汇总清单 | 5 | 综合鉴定完成 |
| 待销毁审批 | 6 | 清单已定稿 |
| 待出库审批 | 7 | 销毁审批通过 |
| 待实施销毁 | 8 | 出库审批通过 |
| 已完成 | — | 实施销毁完成且闭环 |
| 已驳回 / 已撤回 | — | 终态之一 |

## 5. 数据实体（占位，待对齐 `01_DataModel.md`）

- 销毁申请主单、申请明细（拟销毁档案引用）。
- 各节点审批/鉴定任务记录（操作人、意见、附件、时间戳）。
- 汇总清单版本（冻结快照 ID、与明细关联）。
- 出库单/出库审批记录（若与现有库房/转库模型共用，需标明 FK）。
- 实施销毁回执、销毁报告文档存储引用。
- 与现有 `fdc_disposal_record_t`（若已存在）的映射：**待数据模型定稿后在本节与子文档 §6 补全**。
