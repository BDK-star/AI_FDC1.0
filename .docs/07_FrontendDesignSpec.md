# 前端设计规范（财经文档系统）

本文档合并 **视觉与界面设计规范（FDC-DS）** 与 **页面/交互开发规范**，作为全局前端实现的统一依据。实现细节须同时符合 [@.docs/01_DataModel.md](./01_DataModel.md)、[@.docs/05_API_Conventions.md](./05_API_Conventions.md) 等基准文档。

## 第一部分：设计理念与视觉基础（FDC-DS）

### 1.1 核心设计理念

- **专业性 (Professional)**：深蓝色系主色，体现金融/财经类系统的严谨性。
- **清晰度 (Clarity)**：卡片式布局与充足留白，保证海量数据下的可读性。
- **现代感 (Modern)**：适度使用毛玻璃、微动效与圆角，提升操作体验。

### 1.2 色彩体系 (Color Palette)

| 类型 | 颜色值 | 用途说明 |
| :--- | :--- | :--- |
| **主色 (Primary)** | `#1173d4` | 核心按钮、图标强调、激活状态 |
| **主色-深 (Dark)** | `#0d5bb0` | 按钮悬停、深色背景强调 |
| **主色-浅 (Light)** | `#3d8ce8` | 辅助强调、渐变起点 |
| **背景 (Background)** | `#f6f7f8` | 全局页面底色（可配合渐变） |
| **边框 (Border)** | `#dbe0e6` | 容器边框、分割线 |
| **正文 (Text-Main)** | `#111418` | 标题与核心阅读内容 |
| **次要 (Text-Sec)** | `#617589` | 标签、辅助说明 |
| **成功 (Success)** | `#10b981` | 正常状态、成功提示 |
| **警告 (Warning)** | `#f59e0b` | 异常提醒、警告通知 |

### 1.3 字体规范 (Typography)

- **字体族**：`Microsoft YaHei`（微软雅黑）、`Inter`、`Noto Sans SC`、`sans-serif`。
- **字号与权重**：
  - **页面大标题**：`30px - 48px`，Bold (700)
  - **模块标题**：`20px - 24px`，SemiBold (600)
  - **正文**：`14px`，Regular (400)
  - **辅助/描述**：`12px`，Regular (400)

### 1.4 图标系统 (Iconography)

- 统一使用 **Material Symbols Outlined** 系列（或与设计稿一致的线性图标集）。
- 默认字号：`20px`（表单/列表）、`24px`（标题旁）、`40px+`（核心功能入口）。
- 关键属性示例：`font-variation-settings: 'FILL' 0, 'wght' 400, 'GRAD' 0, 'opsz' 20;`

### 1.5 布局与结构

**页面容器**

- **全局背景**：`linear-gradient(135deg, #f6f7f8 0%, #e8f0f7 100%)`（可与业务壳层协调）。
- **内容宽度**：最大约 `1440px`，超宽屏居中。
- **内边距**：主区域 `24px` 或 `32px`（等价于 Tailwind `p-6` / `p-8` 量级）。

**导航与头部**

- **高度**：约 `64px` 或 `80px`。
- **效果**：背景 `rgba(255, 255, 255, 0.95)`（毛玻璃感）、底部分割线、轻阴影（`shadow-sm` / `shadow-lg`）。

**卡片**

- **基础**：白底、`rounded-xl`（约 12px）、边框、轻阴影。
- **悬停（可选）**：轻微上移 +阴影加深，用于可点击卡片。

### 1.6 交互组件（视觉层）

**按钮**

- 高度约 `36px`–`40px`，圆角约 `8px`。
- 主按钮：主色底 + 白字；次按钮：白底 + 边框 + 主色/正文色字。

**表单输入**

- 高度约 `40px`，圆角 `4px`–`6px`。
- 聚焦：主色描边或 `ring` 高亮。
- 只读：浅灰背景，边框保持可读。

**表格**

- 表头：浅灰底、次要色字、字重略加粗；单元格底部分割线。
- 对齐：文本左对齐，数字右对齐。
- 滚动条：宜使用细滚动条样式，避免抢占视觉焦点。

### 1.7 动效指引

- **入场**：淡入（约 0.6s）、自下而上滑入（约 0.5s）等轻量动效。
- **过渡**：`transition-all duration-300`，缓动 `cubic-bezier(0.4, 0, 0.2, 1)`。

### 1.8 标准页面模板参考（静态原型）

以下路径相对于仓库根目录：

- **查询列表页**：`.docs/features/F03/reference_html/pages/document_search.html`
- **详情/编辑页**：`.docs/features/F03/reference_html/pages/document_edit.html`
- **主门户首页**：`.docs/features/F03/reference_html/index.html`

## 第二部分：开发原则与页面交互规范

### 2.1 开发原则

1. **统一性**：页面风格与操作逻辑一致，降低维护成本。
2. **便捷性**：布局清晰、流程简短；支持多种录入与检索方式，适配不同业务量与操作习惯。
3. **兼容性**：适配 PC 端主流浏览器（Chrome、Edge、Firefox 最新版）；分辨率建议 ≥ **1366×768**，保证布局与交互可用。

### 2.2 通用页面规范

1. **风格**：商务风格；颜色、字体、图标在各页面保持一致。
2. **布局**：自上而下、左右分区；区域之间用容器分隔，避免视觉冲突。
3. **字段**：必填标 `*`；复杂字段宜有悬浮说明；输入类组件样式统一。
4. **选择器边界**：下拉框、日期/月份范围等选择器**不得超出**父容器（卡片、栅格列）右边界。实现上：栅格列使用 `minmax(0, 1fr)`，单元格设置 `min-width: 0`，控件设置 `width: 100%` 与 `max-width: 100%`；跨度较大的控件（如月份范围）可占 **2 列**栅格。全局辅助样式见前端 `src/styles/element-admin.css`（`.page-form-grid` / `.page-summary-grid` 子项与 `.el-form-item__content` 内选择器）。
5. **特定字段**：查询条件中若存在「是否启用」，默认值宜为「是」（与业务确认后落地）。
6. **反馈**：成功/失败/确认需有明确提示；校验失败时字段高亮并展示原因。

### 2.3 创建页规范

1. **布局**：上下分区——上为头信息表单（可折叠），下为明细表格（可折叠）。
2. **字段排布**：每行不超过 **4** 个字段；标签右对齐；输入框宽度约 **180px**，标签与控件间距约 **10px**；表格列字段一列一字段，列间距约 **10px**。
3. **按钮**：须包含 **提交**、**保存**、**取消**；提交为主按钮；按钮间距 **10px**，组内按钮置于页面 **右下**。

### 2.4 查询页规范

1. **布局**：上查询区、下结果列表区。
2. **查询区**：表单展示；单个条件宽度约 **180px**，条件间距 **10px**；一行最多 **5** 个条件；超过两行须有 **展开/收起**；仅保留 **查询**、**重置**，靠 **右** 对齐。
3. **列表区**：表格展示；列宽参考 **180px**（可按字段调整）；列间距 **10px**。
4. **按钮**：默认提供 **导入**、**导出**（若业务需要），置于列表 **上方左侧**，按钮间距 **10px**。
5. **分页**：默认 **20** 条/页；可选 **20 / 50 / 100 / 200**；切换每页条数后自动刷新并重算页码。
6. **查询按钮区统一样式（强制）**：查询区底部的「重置 / 查询」按钮必须复用全局 class `fdc-query-action-buttons`（定义于 `frontend/src/styles/element-admin.css`），禁止页面内重复定义同类样式。后续新增查询页默认沿用此 class，确保按钮高度、间距、对齐方式与移动端行为完全一致。

### 2.5 详情页规范

1. **布局与字段**：与创建页一致（只读场景可弱化编辑控件）。
2. **按钮**：默认提供 **取消**，置于页面 **右下**。

### 2.6 弹窗页规范

1. **布局**：上标题区、下内容区。
2. **标题区**：标题居左，与右侧操作区间距约 **10px**。
3. **内容区**：表单布局；每字段一列，字段间距 **10px**。

### 2.7 可复用样式基线（查询/列表页）

以下规则用于全系统查询与列表页面统一落地，新增页面默认遵循：

1. **查询页三段式结构（强制）**：采用“筛选卡片 + 外置工具栏 + 列表卡片”结构；工具栏不得放入筛选卡片或列表卡片内部。
2. **查询按钮区（强制）**：查询区底部“重置/查询”按钮组统一使用全局 class `fdc-query-action-buttons`（定义于 `frontend/src/styles/element-admin.css`）；不得在页面内重复定义同类样式。
3. **列表右上角标准按钮（强制）**：统一为三个 icon 按钮（`列设置`、`列表栏信息全页面展示`、`刷新`），形态为 `circle + tooltip`；顺序保持一致。
4. **筛选控件宽度一致（强制）**：`el-input`、`el-select`、`el-date-picker` 在筛选栅格中必须同宽（`width:100%`、`max-width:100%`、`box-sizing:border-box`）；时间范围控件不得额外扩宽导致视觉不齐。
5. **必填字段视觉规则（强制）**：必填字段采用“红色星号 + 未填高亮边框 + 关联按钮禁用”组合；提示优先使用字段附近浮层（tooltip/图标），避免使用会改变布局高度的块级提示。
6. **状态驱动禁用规则（推荐）**：当关键前置条件未满足（如未选文档类型）时，查询、更多筛选、批量操作等按钮保持禁用；条件满足后自动恢复。
7. **头部状态与入口布局（推荐）**：状态标签与快捷入口按钮在桌面端同一行展示，小屏允许换行；不得出现同级元素上下错层且无业务理由的布局。

**禁止项：**

- 禁止同一系统内出现多个“查询按钮区”样式版本（颜色、间距、对齐方式不一致）。
- 禁止把“更多筛选条件”按钮做成与查询前置条件无关的可点击状态。
- 禁止通过新增占位提示块（如顶部警示条、字段下方额外文本块）破坏筛选栅格高度对齐。

### 2.8 页面样式自检清单（提交前）

开发与联调提交前，建议逐项勾选：

- [ ] 页面采用“三段式”结构：筛选卡片、外置工具栏、列表卡片。
- [ ] 查询区底部按钮组使用 `fdc-query-action-buttons`，无页面内重复定义版本。
- [ ] 列表右上角含并仅含三个标准按钮：`列设置`、`列表栏信息全页面展示`、`刷新`（icon + tooltip）。
- [ ] 筛选区 `input/select/date-picker` 同宽；时间范围控件与普通字段宽度一致。
- [ ] 关键必填字段有 `*` 标识；未填时字段高亮，关联操作按钮禁用。
- [ ] 必填提示采用字段附近浮层提示，不新增会挤压布局的块级提示。
- [ ] “更多筛选条件”按钮在关键必填未满足时为禁用态。
- [ ] 主按钮颜色、边框、尺寸与 F02 页面基线一致，无局部漂移。
- [ ] 页面在 1366 宽度与移动端断点下均无错位、遮挡、溢出。
- [ ] 全局头部状态标签与快捷入口在桌面端同一行展示，小屏可换行。

### 2.9 日期时间统一规范（查询/列表/详情）

1. **筛选控件（强制）**：除“开始档期/结束档期”外，所有日期时间筛选字段统一使用“日期（年月日）”选择器。
2. **档期字段（强制）**：`start_period`、`end_period` 按 `YYYY-MM` 展示与筛选，不纳入“时分秒展示”规则。
3. **列表展示（强制）**：非档期时间字段统一展示为 `yyyy-MM-dd HH:mm:ss`。
4. **详情展示（强制）**：非档期时间字段统一展示为 `yyyy-MM-dd HH:mm:ss`。
5. **接口协同（强制）**：前端发送查询条件使用日期字符串（`YYYY-MM-DD`），后端负责扩展为时间范围（当天 `00:00:00` 到 `23:59:59`）。

**日期时间自检补充：**

- [ ] 非档期时间字段在列表页显示为 `yyyy-MM-dd HH:mm:ss`。
- [ ] 非档期时间字段在详情页显示为 `yyyy-MM-dd HH:mm:ss`。
- [ ] 查询栏日期字段为“年月日”选择器，且不会改变栅格宽度与布局。
- [ ] 开始档期/结束档期仍按 `YYYY-MM` 展示与查询。
