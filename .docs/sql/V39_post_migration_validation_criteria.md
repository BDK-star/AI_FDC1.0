# V39 迁移结果判定标准

适用脚本：`/.docs/sql/V39_post_migration_validation.sql`

## 1. 行数对比

- **通过**：`row_count_legacy == row_count_new`
- **阻断**：两者不相等（说明迁移丢失/重复）

## 2. ID 映射完整性

- **通过**：`missing_doc_id_count = 0`
- **阻断**：`missing_doc_id_count > 0`

## 3. 必填字段空值检查

- **通过**：所有 `check_value = 0`
- **阻断**：任一必填项 `check_value > 0`

备注：若历史数据质量差导致个别字段无法满足，可先评审并形成豁免清单，再决定是否上线。

## 4. 关联完整性（外键悬挂）

- **通过**：`orphan_document_attach = 0` 且 `orphan_arch_storage = 0`
- **阻断**：任一值大于 0

## 5. 业务键重复（tenantid + doc_biz_no）

- **通过**：查询结果 0 行
- **阻断**：查询结果非 0 行（存在重复业务键）

## 6. 状态分布检查

- **通过**：`lifecycle_status` / `custody_status` 分布与业务预期一致，无异常新值暴增
- **预警**：出现未知状态码或单一状态占比异常升高（需人工确认）

## 7. 抽样检查（最新 20 条）

- **通过**：关键字段（`doc_biz_no`、`company_code`、`doc_name`、状态、时间字段）可读且符合预期
- **预警**：大量默认值（如 `UNKNOWN`、`0`、`1.0`）集中出现，应回看映射规则

## 上线决策建议

- **可执行 V40 清理备份表**：1~5 全通过，6~7 无异常或异常已确认可接受
- **暂缓执行 V40**：任一阻断项不通过，或预警项未确认
